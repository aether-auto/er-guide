# Elden Ring 100% Route Guide — Design Spec

**Date:** 2026-06-09
**Status:** Approved pending user review
**Deploy target:** GitHub Pages (`aether-auto/er-guide`)

## 1. Product

An open-source, not-for-profit static website: a grace-to-grace walkthrough of all of Elden Ring (base game + Shadow of the Erdtree DLC) that doubles as a persistent collection checklist. The user follows one optimal route; every useful unique item appears as a checkable step at the point in the route where it is naturally collected. The site answers two questions: "where do I go next?" and "do I have everything?"

Non-goals: lore, build guides, boss strategy, farmable consumables/crafting materials, pure cosmetics (gestures, paintings).

### Item scope (in)

Weapons, shields, staffs/seals, arrows/bolts (unique only), armor pieces, talismans, sorceries, incantations, ashes of war, spirit ashes, key items, golden seeds, sacred tears, crystal tears, memory stones, larval tears, whetblades, stonesword keys, bell bearings, cookbooks, map fragments, great runes, remembrances, flask upgrades, Scadutree fragments, Revered Spirit Ash, DLC equivalents of all the above. Roughly 3,000–4,000 entries.

### Item scope (out)

Farmable/infinite consumables, crafting materials, smithing/somber stones found loose in the world (their **bell bearings** are in scope — that's the permanent unlock), gestures, paintings, info notes.

## 2. Architecture overview

Two layers with a hard boundary:

1. **Item database (generated by scripts).** One canonical `items.json` produced by an ETL pipeline from online sources. Contains every in-scope item with category, acquisition text, missable info, and map coordinates/marker id.
2. **Route (hand-authored).** Per-region JSON files defining the ordered walkthrough: regions → legs (grace A → grace B) → steps. Item steps reference the database by `id` only — no item data is duplicated into the route.

The site is a Vite + React + Tailwind SPA that consumes the merged output of both layers from `public/data/`. A validation script is the gate between the layers and CI runs it on every push.

## 3. Data pipeline (`scripts/`)

Node scripts, run locally (results committed; the site never fetches third-party data at runtime).

### Sources

| Source | What it provides | Access |
| --- | --- | --- |
| Fextralife interactive map (eldenring.wiki.fextralife.com/Interactive+Map) | Marker id, lat/lng, marker title/category for every mapped item, for both the overworld/underground maps and the DLC map | The map app loads marker data as JSON; the fetch script discovers and calls those endpoints, caching raw responses |
| eldenring.wiki.gg (MediaWiki API) | Authoritative item lists per category, per-item pages (acquisition text, missability), DLC coverage | `api.php` category/page queries |
| Elden Ring Fan API (eldenring.fanapis.com) | Clean base-game item catalog (names, categories, descriptions) for cross-checking | Open JSON API |

Attribution for all sources goes in the README and the site footer; wiki content is community-licensed and this project is non-commercial.

### Commands

- `npm run fetch` — download all raw source data into `scripts/cache/` (idempotent; cached files committed so builds are reproducible and polite to the sources).
- `npm run build-data` — normalize, dedupe, and merge cache into `data/items.json`: match wiki items to map markers by name (with a manual-overrides file `data/overrides.json` for fuzzy cases), assign stable slug ids, attach map deep-link parameters.
- `npm run validate` — see §7.

### Item record schema

```json
{
  "id": "talisman-radagons-soreseal",
  "name": "Radagon's Soreseal",
  "category": "talisman",
  "dlc": false,
  "acquisition": "Fort Faroth, on a corpse behind the rot-covered ladder room.",
  "missable": null,
  "quest": null,
  "map": { "code": "overworld", "markerId": 4605, "lat": -95.5, "lng": 110.5 },
  "wikiUrl": "https://eldenring.wiki.gg/wiki/Radagon%27s_Soreseal"
}
```

`missable`, when set, is `{ "lockedBy": "...", "note": "..." }` (e.g. locked by burning the Erdtree, by a quest failure, or by a boss kill). `map` may be `null` if no marker matched — validation reports these as gaps. `map.code` is one of `overworld`, `underground`, `dlc`.

## 4. Route data (hand-authored)

`data/regions/NN-slug.json`, ordered by filename prefix. Canonical route order: Limgrave → Weeping Peninsula → Stormveil → Liurnia → Ainsel/Siofra detours → Caelid → Altus (Ruin-Strewn Precipice) → Mt. Gelmir → Leyndell → Mountaintops → Mohgwyn Palace → Consecrated Snowfield → Haligtree → Shadow of the Erdtree (entered after Radahn + Mohg) → Crumbling Farum Azula → Leyndell, Ashen Capital → endings.

```json
{
  "id": "limgrave",
  "name": "Limgrave",
  "order": 1,
  "legs": [
    {
      "id": "limgrave-01",
      "from": "The First Step",
      "to": "Church of Elleh",
      "summary": "Head north past the Tree Sentinel (skip him for now)...",
      "steps": [
        { "type": "direction", "text": "Hug the right cliffside going north." },
        { "type": "item", "itemId": "spirit-ash-lone-wolf-ashes", "note": "From Renna at the church at night — rest until nightfall if she isn't there." },
        { "type": "quest", "questline": "Ranni", "text": "Talk to Renna to receive the Spirit Calling Bell.", "before": null },
        { "type": "boss", "text": "Optional: Tree Sentinel", "itemId": "weapon-golden-halberd" }
      ]
    }
  ],
  "cleanup": ["item-ids-not-placed-in-any-leg-yet"]
}
```

Step types: `item` (checkable, joined with the database record at build time), `direction`, `boss` (checkable; may carry an `itemId` drop), `quest` (checkable; NPC questline steps interleaved at the exact route point where they must happen, with missable warnings when they're gated by upcoming progression). Every region has a `cleanup` array: in-scope items located in that region but not yet woven into a leg — rendered as a "sweep" section at the end of the region so the guide is complete even where the route prose is not yet polished.

## 5. UI

Single-page app, dark Elden Ring–styled theme (gold accents, serif display headings).

- **Left sidebar:** region/leg tree with per-node progress bars; click to jump. Collapsible.
- **Center:** current leg — summary paragraph, then ordered steps. Item steps show a category icon, name, acquisition note, missable badge (loud, amber), checkbox, "show on map" button, wiki link. Boss/quest steps are also checkable.
- **Right panel** (collapsible; bottom sheet on mobile): the Fextralife interactive map in an `iframe`. "Show on map" sets the iframe `src` to the item's deep link (`https://eldenring.wiki.fextralife.com/Interactive+Map?id=<markerId>&lat=<lat>&lng=<lng>&zoom=8&code=<mapcode>`), jumping the map to the pin. Every item also gets an "open map in new tab" fallback link in case embedding is blocked.
- **Top bar:** global item search (jumps to the item's route position), category filter chips, "hide completed" toggle, overall progress.
- **Dashboard route (`/progress`):** totals per category (e.g. Talismans 61/91) and per region; list of unchecked missables you've routed past (the "you are about to lose these" warning).
- **Coverage route (`/coverage`):** generated data-quality report — items missing map markers, items not placed in any leg (auto-derived; this is the contributor to-do list).

## 6. Progress persistence

- `localStorage`, single key, value `{ schemaVersion, profile, checked: { [id]: timestamp } }`.
- Export/import as a JSON file (backup + cross-device).
- Profiles: support a second profile for NG+ (switcher in top bar); "reset" creates a new profile rather than wiping.
- Checking an `item`/`boss`/`quest` step is the same mechanism — one id namespace.

## 7. Validation (`npm run validate`, runs in CI)

- Schema-check every item and region file; ids unique and stable.
- Every `itemId` referenced by a route step exists in `items.json`.
- Every item in `items.json` is referenced by exactly one route step **or** appears in exactly one region `cleanup` list — nothing unplaced, nothing double-placed.
- Per-category counts compared against an expected-totals file (`data/expected-counts.json`, sourced from wiki category totals); mismatches print as warnings with the diff.
- Items with `map: null` counted and listed (feeds `/coverage`).

## 8. Build & deploy

- Vite + React + TypeScript + Tailwind. React Router with hash routing (no 404 config needed on Pages).
- GitHub Actions workflow: on push to `main` → `npm ci`, `npm run validate`, `npm run build` (with `base` set for project pages), deploy `dist/` via `actions/deploy-pages`.
- No backend, no runtime third-party fetches except the map iframe.

## 9. Error handling

- localStorage read wrapped with schema-version check; unknown version → offer export of raw blob, then re-init (never silently wipe).
- Import validates shape before applying; bad file → error toast, no state change.
- Iframe load failure is not detectable cross-origin — the persistent "open in new tab" link is the mitigation.
- Items with no map marker render the button disabled with a tooltip ("no marker yet — see wiki link").

## 10. Testing

- `npm run validate` is the primary gate (CI-blocking).
- Vitest unit tests: progress store (check/uncheck/profiles/migration), import/export round-trip, search/filter selectors.
- Manual smoke per region during data authoring: spot-check 3–5 map deep links resolve to the right pin.

## 11. Risks

- **Fextralife marker endpoint shape may change or be undocumented** — mitigated by committing the raw cache and by the manual-overrides file; worst case, deep links still work with lat/lng only.
- **Name-matching wiki items to map markers is fuzzy** — mitigated by `overrides.json` and the coverage report making mismatches visible.
- **Route prose for 20+ regions is a lot of authoring** — mitigated by the `cleanup` mechanism: the site is *complete* (every item checkable, mapped, in the right region) even before every leg is beautifully written. Route polish can land region by region.
