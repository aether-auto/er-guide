# Map v2: Custom Integrated Leaflet Map — Plan Addendum

> Supersedes the embedded-map design (mapgenie panel + Fextralife companion window) from the main plan.
> User requirement: the map must be fully interactive WITH the guide — pins for graces/items, checked-state styling
> synced to progress, per-item center+zoom in-app, route path drawing per leg as the route gets authored.

**Why this is feasible with zero coordinate work:** the Fextralife map app is Leaflet `CRS.Simple` with a public
tile pyramid per layer (`<iframe-path>/map-tiles.<n>/{z}/{x}/{y}.jpg`, zoom 0–7, verified live 2026-06-10), and our
entire marker dataset (`scripts/cache/map/*.json`, 5,111 markers) is **already in that coordinate space** (`x`=lat,
`y`=lng). Replicating the tile config in our own Leaflet makes every marker drop in exactly.

## Task M1: Tile mirror + graces extraction

**Files:** Create `scripts/fetch-tiles.mjs`, `scripts/build-map-extras.mjs`; output `public/tiles/{code}/{z}/{x}/{y}.jpg`
(code ∈ overworld|underground|ashen|dlc) and `data/map-extras.json`.

1. For each of the four iframe URLs in `scripts/sources.json` (`map.fextralife.iframes`), fetch the iframe HTML and
   extract: the tileLayer URL template (pattern `tileLayer\('([^']+)/{z}/{x}/{y}\.jpg'`), minZoom/maxZoom, and any
   bounds/size config present. The mapA template is verified:
   `/file/Elden-Ring/map-50be4728-3907-4f33-8857-7f063e0d24eb/map-tiles.4/{z}/{x}/{y}.jpg` (zoom 0–7, CRS.Simple).
   Other layers follow the same shape with their own UUID and possibly a different `.n` tiles version.
2. Mirror the pyramid for **z0..6** (skip z7 — size; the UI uses `maxNativeZoom` + Leaflet upscaling for z7).
   Tile existence discovery: parse bounds from the HTML if present; otherwise probe — at each z, expand a frontier
   from known-good tiles (parents of existing tiles at z-1 have children at 2x,2y..2x+1,2y+1; verify by HEAD/GET,
   404 = outside map). Politeness: ≤2 concurrent, ~150ms delay between requests, browser UA, resume support (skip
   files that already exist on disk), retry 3x on 5xx.
3. Budget: target **< 250MB total**. Print per-layer tile counts + bytes. If over budget: recompress with `sharp`
   to webp q72 (rename template to .webp and have the UI use it), or cap underground/ashen at z5 (they're smaller
   maps anyway). Record final stats in the commit message.
4. `scripts/build-map-extras.mjs`: from the cached marker JSONs, extract all markers whose category is the grace
   category (inspect the cached `categories` arrays for the exact name, e.g. "Site of Grace") into
   `data/map-extras.json`: `{ "graces": [{ "code", "markerId", "name", "lat", "lng" }] }`. Deterministic output
   (sorted). Graces are NOT items — they never appear in items.json or the checklist; this file is map-display data.
5. Commit tiles in a few chunked commits if needed (`git add public/tiles/overworld && git commit ...` etc.).
   Update `.gitignore`? No — tiles are deliberately committed (CI must not re-download from Fextralife each build).

**Acceptance:** all four layers mirrored z0..6 with no holes (spot-check: the z2 tile grid for overworld renders a
complete map when stitched — verify a few mid-zoom tiles open as valid JPEGs); map-extras.json contains ~300 graces
(base) + DLC graces; total size reported and < 250MB.

## Task M2: Map-first guide UI + MapView integration (REVISED per user direction 2026-06-10)

User direction: "the map look like the map genie map with the nice markers", "ability to draw paths or explain if
something is not straightforward to find", "guide designed as a small list of running items to keep marking off and
the next sight but with a LARGE map view along with it", "instructions on how to find stuff, what interactions to
do, quest items and npc questlines".

**Files:** Create `src/components/MapView.tsx`, `src/components/RoutePanel.tsx`, `src/lib/route-path.ts` (+ test),
`src/lib/markers.ts` (icon/marker styling helpers); Modify `src/App.tsx`, `src/pages/GuidePage.tsx`,
`src/components/{StepRow,TopBar}.tsx`, delete `src/components/MapPanel.tsx`, `src/lib/maplink.ts`, spec §5, README.

**Deps:** `leaflet`, `@types/leaflet` (plain Leaflet in a ref'd div recommended — full control over CRS, divIcons,
panes; avoid react-leaflet unless you verify it faster).

### 1. Layout flip — the map IS the page

Desktop `/region/:id(/:legId)`: **full-viewport MapView as the canvas** (under a slim TopBar). Overlaid on the left:
a fixed **RoutePanel** (~360–400px, panel background, scrollable) = the "small running list". Mobile: map full-screen,
RoutePanel as a bottom sheet (collapsed → drag/tap to expand). `/progress` + `/coverage` pages unchanged.

**RoutePanel contents (top to bottom):**
- Region title + leg navigation (prev/next leg buttons + current leg name, or "Region sweep" mode when no legs).
- **"Next up" callout**: the first unchecked checkable step — name, how-to-find note, big check button, auto-focused
  on the map (distinct pulsing marker). Checking it advances to the next unchecked step and pans the map.
- The running list: ordered steps of the current leg (or cleanup), unchecked first emphasis, checked collapsed to
  thin strikethrough rows. Each row: checkbox, name, category chip, missable badge, locate-on-map button.
- Compact progress bar (leg + region), link to the full region tree (drawer or dropdown), search stays in TopBar.

### 2. MapView — Map Genie-quality markers

Leaflet, `crs: L.CRS.Simple`, local tiles `${import.meta.env.BASE_URL}tiles/${code}/{z}/{x}/{y}.jpg`
(`minZoom 0, maxZoom 7, maxNativeZoom 6, noWrap`), dark background color matching the theme.
- **Markers via `L.divIcon` styled like Map Genie**: circular badge (~28px), category-colored ring + glyph
  (define a CATEGORY_GLYPH/COLOR map in `src/lib/markers.ts` — unicode/SVG glyphs: ⚔ weapons, 🛡 shields/armor,
  ◉ talismans, ✦ sorceries, 🔥 incantations, 👻 spirit ashes, 🗝 key items, 🌱 golden seeds, ⚗ crystal tears, etc. —
  consistent, readable at a glance; CSS in index.css). **Graces**: the iconic gold grace glow (radial-gradient dot).
  **Checked items**: desaturated + ✓ overlay + reduced opacity. **"Next up"**: pulsing halo animation.
- **Pin popup** (the "wiki instructions" surface): item name, category, full acquisition/how-to-find text, step
  `note` if routed, missable warning, quest context (`item.quest` / quest step text), wiki link + Fextralife link
  (`mapUrl(ref)`), check/uncheck button (two-way sync with the store).
- **Layer switcher** tabs (Overworld/Underground/Ashen/DLC) top-right of the map + graces toggle; auto-switch on
  focus of an item on another layer; default `dlc` for DLC regions.
- **Route paths**: per-leg polylines via `route-path.ts` (ordered coords of same-layer item steps; pure + tested),
  gold `opacity .45`; the active leg full-opacity and wider; dashed segment from the current "next up" marker to the
  following step as the immediate direction cue. Where an item has no marker or pathing is meaningless, the
  EXPLANATION carries the load: its note/acquisition text in the popup and RoutePanel row (user-approved fallback).
- **focus(ref, itemId?)** in UiContext: switch layer → `flyTo([lat,lng], 6)` → open popup. RoutePanel rows and
  StepRow's map button call it. Map↔list two-way: popup check updates list instantly (shared store).
- invalidateSize on mount/layout changes; persist last layer+graces-toggle in sessionStorage (nice-to-have).

### Content bar for route authoring (applies to main-plan Tasks 17–24)

Every item step's `note` must carry the HOW when it isn't trivial: required interactions ("rest until night",
"illusory wall — strike it", "ride the wind lift"), purchase source + cost, quest prerequisites ("requires giving
Sellen the Sellian Sealbreaker first"), and boss/quest gating. Quest steps must state the exact action + place +
consequence of skipping (missable flag). The RoutePanel/popup renders these verbatim — they ARE the wiki layer.
